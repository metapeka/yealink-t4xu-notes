    Прошивка по сети, без паяльника

    Пакет .rom заливается в трубку через её собственный веб-интерфейс. Ни UART, ни программатор для записи не нужны — они нужны только чтобы читать (дамп флеша, лог загрузки).

    1. Узнать адрес трубки

    • На самой трубке: OK → Status → IPv4 (или в разделе Network).
    • Либо в списке клиентов роутера, по MAC.

    2. Открыть веб-интерфейс

    http://<IP трубки>

    Логин по умолчанию — admin. Если пароль меняли, нужен он.

    3. Раздел обновления

    [гипотеза] путь может отличаться по версиям ПО:

    • Settings → Upgrade
    • либо Admin → Upgrade / Advanced → Firmware

    Там поле «файл прошивки» и кнопка загрузки. Выбираешь наш .rom и запускаешь.

    4. Требования к пакету

    • Формат — тот же .rom (T46U(T43U,...)-<версия>.rom), пересобранный нашими инструментами.
    • Версия в пакете должна быть выше текущей — иначе интерфейс откажется ставить «старую прошивку». Сейчас на трубке 108.86.14.4, значит в пакете — 108.86.14.99 и выше.
    • Перед обновлением отключить Auto Provision и RPS, чтобы аппарат не поднялся сам на 87.x.

    5. Отдавать пакет с ПК

    Два способа:

    1. Вручную — просто выбрать файл в веб-интерфейсе трубки.
    2. Провижининг — отдать пакет по HTTP с ПК:
    python -m http.server 8000 --bind 0.0.0.0 --directory /путь/к/пакету

    и указать в настройках трубки URL прошивки на этот адрес.

    [гипотеза] авто-провижининг Yealink ожидает конкретный формат имени файла и .cfg-описание; точный шаблон надо сверять по логу запросов трубки.

    6. Что нельзя делать без подготовки

    • Прошивать рабочую трубку, не проверив пакет на доноре.
    • Прошивать без возможности восстановления: при ошибке понадобится программатор.

    7. Сравнение с аппаратным путём

    Задача Нужен паяльник / UART
    Залить наш пакет нет — сеть и веб-интерфейс
    Снять дамп флеша да (или maskrom по USB)
    Лог загрузки, консоль U-Boot UART, три провода без пайки
    Восстановление после неудачи да, программатор

    Диагностика через провижининг

    Цель: получить на трубке больше, чем веб-интерфейс — логи и, если повезёт, оболочку.

    Что попробовать по порядку

    1. Веб-интерфейс — раздел настроек: посмотреть, есть ли пункты диагностики, «System Log», «Remote Control», «TR-069».
    2. Свой файл конфигурации — положить на TFTP/HTTP и указать его как сервер автоконфигурации. Трубка заберёт файл при следующей загрузке или по таймеру.
    3. Скан портов после включения: 22, 23, 80, 443. Появление нового порта — сигнал, что настройка сработала.

    Шаблон файла

    Формат Yealink — текстовый, вид параметр = значение. Ниже минимальный набор, который стоит проверить [гипотеза]: имена параметров зависят от прошивки, поэтому сначала смотрим, что трубка уже пишет в свой конфиг, и повторяем стиль.

    # диагностика и доступ
features.telnet_enable = 1
features.ssh_enable = 1

# служебные логи
static.auto_provision.weekly.enable = 1
static.auto_provision.custom.sync = 1

# отключаем внешние сервисы, чтобы ничего не тянуло конфиг извне
static.auto_provision.rps.enable = 0

    Как проверить, что сработало

    • В логе трубки (если он доступен) появляется строка о применении конфигурации.
    • После перезагрузки открывается новый порт — проверять сканером, не на глаз.
    • Если ничего не изменилось, значит имя параметра другое: искать в выгрузке текущей конфигурации то, что уже присутствует, и менять по образцу.

    Ограничения

    • Публиковать файл с серийником и MAC нельзя — только шаблон без идентификаторов.
    • Включённый Telnet не должен оставаться включённым дольше сессии: это открытый порт в сети.
