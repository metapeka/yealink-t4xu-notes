    План работ с трубкой (T4xU) — последовательность и гейты

    Сводка веток и памятка для человека с трубкой — BRANCHES.md.

    Документ фиксирует порядок действий. Каждый шаг имеет условие перехода; при провале гейта дальше не идём. Терминология: донор — трубка, на которой допускается кирпич; рабочая — та, что должна работать.

    0. Подготовка (без изменений в устройстве)

    1. Записать текущую прошивку трубки: Web UI → Status (версия, модель, HW rev).
    2. Если версия 108.86.0.80 — это V3 hardware, она принимает только эту версию; дальше не идём, нужен другой аппарат.
    3. Найти/подготовить донора (второй такой же аппарат).
    4. Оформить тикет в Yealink на recovery-файл для модели (без него recovery только через U-Boot консоль/TFTP).
    5. Зафиксировать доступы: есть ли UART-пятаки на плате, есть ли программатор NAND/eMMC.
    6. Скачать и сохранить официальные ROM: 108.86.0.118, 108.87.0.20 (эталоны сравнения).

    Гейт 0: известна версия на трубке и есть донор. Иначе дальше нет смысла.

    1. Ветвление по версии

    Версия на трубке Маршрут Почему
    ≤ 108.86.0.118 A. Софт-маршрут tool-блок этой версии проверяет только magic/CRC/размеры (факт, §5 FINDINGS)
    108.87.x B. Неопределённость tool-блок 87.0.20 содержимое не проверяет, но проверка может быть в библиотеках rootfs или в U-Boot

    2. Маршрут A (телефон ≤ 86.0.118)

    A1. Контроль

    1. Залить на донора официальный 108.86.0.118 тем же путём, которым будем заливать мод (Web UI или Auto Provision).
    2. Убедиться, что апдейт проходит и трубка грузится.

    Гейт A1: путь обновления рабочий на доноре.

    A2. Безобидная перепаковка

    1. Залить artifacts/test_108.86.0.119.rom (изменена только строка версии, CRC пересчитан).
    2. Проверить: версия сменилась, трубка работает.

    Гейт A2: - принято → структурная проверка подтверждена, идём дальше; - отказ → снять syslog/UART-лог, найти строку ошибки, вернуться к анализу .118 tool-блока.

    A3. Проверка нашего LZMA

    1. Собрать ROM, где rfs распакован и заново сжат нашим liblzma без изменений содержимого.
    2. Залить на донора.

    Гейт A3: если грузится — наш компрессор совместим; если нет — подбирать параметры/энкодер до совпадения.

    A4. Слой ubifs crypto — предусловие любых правок rootfs

    Правка ФС невозможна, пока не решён этот слой. Причём это не «только суперблок»: 315 из 331 LEB тома начинаются с vendor-узла ubifs crypto (magic 0x05902638), плаинтекстовых UBIFS-LEB всего 9. Пересжатие всего rfs (A3) этого не требует, а добавление файла — требует.

    Два варианта, оба дорогие:

    • A4a. Ключ. Достать ключ через Holtek (challenge-response, как в публичном разборе T4XS): нужен доступ к телефону и, скорее всего, логический анализатор. Даёт оффлайн-сборку валидной ФС.
    • A4b. Свой U-Boot. Снять ubifs crypto/secure boot check патчем загрузчика → ФС можно собирать обычным mkfs.ubifs. Требует полного дампа флеша (см. A5).

    Гейт A4: выбран и подтверждён один из вариантов. До этого шага пункт «добавить маркер в rootfs» не выполняется.

    A5. Патч U-Boot — предусловие A4b (и, вероятно, A4a)

    1. Полный дамп флеша с донора (программатор или U-Boot nand read + TFTP) — обязательно.
    2. Патч: secure boot check → пропуск, ubifs crypto → обычный UBIFS.
    3. Заливка в uboot (и копию) через ROM-пакет.
    4. Проверка: донор грузится, консоль доступна.

    Гейт A5: донор загружается с patched U-Boot.

    Помнить: ubl пакет не трогает, но при нерабочих обеих копиях uboot устройство не загрузится.

    A6. Первая своя правка rootfs

    1. Добавить в ФС безвредный маркер (файл/строку в скрипте), собрать образ, залить.
    2. Проверить наличие маркера на устройстве.

    Гейт A6: правка доехала → пайплайн «свои функции» рабочий.

    Зависимости: A3 (независим) → A4 (нужен ключ или A5) → A6. Порядок «A4 раньше A5» неверен: без дампа и патча загрузчика правка ФС упирается в риск кирпича.

    3. Маршрут B (телефон 87.x)

    1. Достать библиотеки из rootfs 87.x — упирается в AES-256 (0x83) для app-блока.
    2. Найти ключ 0x83: трассировка [r11-0x1c] в 0x7f778 (Ghidra), проверить, выводится ли он из полей файла.
    3. Если ключ аппаратный (Holtek) — маршрут B без донора и UART не закрывается: переходить к железу.

    Гейт B1: ключ 0x83 получен из файла → распаковка rootfs 87.x и поиск реальной проверки пакета. Гейт B2: ключ аппаратный → аппаратный маршрут (UART + дамп флеша) либо отказ от перепрошивки в пользу Auto Provision.

    4. Правила безопасности (обязательные)

    1. Никогда не прошивать рабочую трубку первой.
    2. Перед любой прошивкой с правкой bootloader — полный дамп флеша.
    3. Каждый шаг — один ROM с одним изменением; лог (UART/syslog) сохранять.
    4. Держать под рукой официальные ROM и recovery-файл.
    5. Не трогать ubl и trust (в пакет не входят, но не пытаться писать туда вручную).

    5. Что нужно от владельца устройства

    1. Версия прошивки и HW rev с трубки.
    2. Донор (второй аппарат) и разрешение на риск.
    3. Ответ: есть ли физический доступ (разборка, UART, программатор).
    4. Recovery-файл Yealink (тикет) — если получится.

    6. Если декомпиляция не даёт результата

    Декомпиляция работает (апдейтер разобран), но три вещи упираются в данные/ключи. Варианты по возрастанию цены:

    1. Эмуляция FUN_00082170 (Unicorn, хуки SHA1/256/512 и OpenSSL) — снять готовый 550-байтный DER публичного ключа. Телефон не нужен.
    2. Ручная сверка ассемблера стадий FUN_0007d820 / 7dc00 / 7e0a0 — функции маленькие, ошибка модели почти наверняка там.
    3. Динамика на устройстве: UART-консоль, запуск апдейтера на телефоне, лог.
    4. Железо: дамп флеша (U-Boot/rootfs в открытом виде), логический анализатор на линии Holtek.
    5. Обход: V86-ветка (.118) — там проверки только структурные, шифр 0x83 не используется.
    6. Без прошивки: Auto Provision + XML Browser + Action URI.
    7. Вендорские данные: recovery-файл, старые ROM — иногда содержат незашифрованные части.

    Два вопроса закрыты не до конца и решатся первым контактом:

    1. Режим тома — гипотеза ECB; подтверждается расшифровкой LEB 0 реальным ключом (tools/ubi_trykey.py).
    2. Код проверки ubifs crypto — в uboot.elf статических ссылок нет (образ релоцируется), нужен лог UART.

    Порядок при появлении доступа: UART и полный лог → дамп всех разделов вместе с OOB → сниффинг шины → только затем пробная запись пакета.
